# Ядро аудита — проверено вручную (2026-09-09)

Всё ниже проверено запросами к продакшену и чтением кода репозитория, а не выводами моделей.

## 1. Индексация и вход на сайт

### C1. Корень отдаёт 307 по Accept-Language, Googlebot попадает на албанскую версию
```
curl -I https://www.domlivo.com/                      -> 307 -> /sq
curl -H "Accept-Language: en-US" ...                  -> 307 -> /en
curl -A "Googlebot/2.1" https://www.domlivo.com/      -> 307 -> /sq
curl -I https://domlivo.com/                          -> 307 -> https://www.domlivo.com/  (и дальше ещё 307)
```
`routing.defaultLocale = "sq"` (`src/i18n/routing.ts:5`). Googlebot не шлёт `Accept-Language`, поэтому он всегда получает `/sq`.
При этом `x-default` в hreflang указывает на `https://www.domlivo.com/` — то есть на URL, который сам является редиректом.

Последствия: главная точка входа для международного бота — албанская страница; апекс→www→локаль это цепочка из двух временных (307) редиректов.

**Severity: High.** Апекс→www сделать 308/301. `x-default` направить на реальную страницу (`/en`) вместо редиректа. Определение языка оставить, но убедиться, что Google видит `/en` как самостоятельную точку входа (ссылка в футере/шапке, ссылка из sitemap — уже есть).

### C2. Служебные страницы закрыты корректно — это не проблема
```
/en                     200, robots-мета нет
/en/albania/durres      200, robots-мета нет
/en/durres              200, noindex, follow + canonical -> /en/albania/durres
/en/ai-search           200, noindex, follow
/en/favorites           200, noindex, follow
```
Старые бескантрийные URL городов закрыты `noindex` и канониклятся на новый путь. Сделано правильно, править нечего.

## 2. hreflang

### C3. hreflang живёт только в HTTP-заголовке `Link:` — ни в HTML, ни в sitemap
На листинге `/en/property/…` в HTML нет ни одного `<link rel="alternate" hreflang>`; все семь значений (6 локалей + x-default) приходят заголовком `Link:`. В `sitemap-properties.xml` нет `xhtml:link` — только `<loc>` и `<lastmod>`.

Google заголовки поддерживает, так что формально это работает. Но:
- это единственный канал: любая потеря заголовка (CDN, прокси, кэш) убивает всю международную разметку разом;
- сторонние краулеры и аудиторы (в том числе Ahrefs/Screaming Frog в дефолтной конфигурации) заголовок часто не читают — отсюда и ощущение «hreflang не работает»;
- заголовок `Link:` на этом сайте уже большой (в нём же preload шрифтов и CSS).

**Severity: High.** Продублировать hreflang `xhtml:link`-альтернативами в sitemap (самый дешёвый и надёжный канал для 1767 URL) и/или тегами в `<head>`.

## 3. Контент листингов

### C4. В описаниях осталась реклама агентства-источника
Пример `/en/property/…-spille-154` (после чистки эмодзи):
> Get fully dedicated service at FIND ALL SPILLE
> Call | What's app | Viber | DM
> Find the property your want
> Real Estate Agency in Albania

Это дословный текст стороннего агентства, размноженный по 6 локалям на десятках объявлений. Для Google это шаблонный дублирующийся блок + упоминание чужого бренда; для покупателя — призыв уйти к конкуренту.

**Severity: High.** Вырезать хвост «контакты/призыв» из импортированных описаний скриптом (он однотипный) — по аналогии с `stripListingEmoji.ts`.

### C5. 45 из 152 объявлений всё ещё с эмодзи в описании
Шесть, ломавших ИИ-ассистента, вычищены 09.09.2026. Остальные 45 безвредны технически, но выглядят как некопирайченный импорт. `npm run strip:listing-emoji -- --all --execute` в `domlivo-admin` закрывает вопрос.

**Severity: Medium.**

### C6. Слаги листингов — русская транслитерация во всех локалях
`/en/property/prodazha-kvartiry-11-u-morya-or-70-m-do-plyazha`, `/en/property/novyy-6-etazhnyy-dom-v-goleme-ryadom-s-morem`.
Английская, албанская, польская, итальянская версии живут по русско-транслитерированному URL. Слаг — слабый фактор, но здесь он ещё и сигнал «страница не для этого языка», и он попадает в выдачу как видимый текст URL.

**Severity: Medium.** Для новых объектов генерировать слаг из английского названия; старые не трогать без 301 (или трогать с 301, разом, до того как страницы наберут вес — сейчас как раз момент, когда терять нечего).

## 4. Разметка (Schema.org)

Проверено на живых страницах.

### Хорошо — трогать не нужно
- **Листинг**: `RealEstateListing` + `Apartment` (accommodation) + `Product` + `Offer` + `PropertyValue`×4 + `PostalAddress` + `QuantitativeValue` + `BreadcrumbList`. Разделение «страница / жильё / коммерция» сделано осознанно (`src/lib/seo/propertyJsonLd.ts`), площадь в `MTK`, цена в EUR. Это лучше, чем у большинства конкурентов.
- **Главная**: `Organization` + `WebSite` + `SearchAction` + `FAQPage` (10 вопросов) + `ContactPoint` + `ImageObject`.
- **Город**: `BreadcrumbList` + `ItemList` (27 позиций).

### C7. В `Organization` телефон-заглушка
```json
"contactPoint": {"@type":"ContactPoint","telephone":"+355 69 000 0000","email":"hello@domlivo.com"}
```
Настоящий номер на сайте — `+355 68 928 6136`. В разметке — очевидная заглушка `69 000 0000`. Это тот телефон, который Google читает как атрибут сущности бренда.

**Severity: Critical** (по цене исправления — минуты, по последствиям — неверный NAP у сущности).

### C8. `Organization` вместо `RealEstateAgent`, и без `address`
Тип `Organization` не даёт локальных сигналов. Для агентства недвижимости корректен `RealEstateAgent` (подтип `LocalBusiness`) с `address` (`PostalAddress`), `areaServed`, `geo`, `openingHours`. В CMS адрес хранится строкой `companyAddress: "Tirana, Albania"` — в разметку он вообще не попадает, а «Tirana, Albania» это не адрес.

**Severity: High.**

### C9. У городских страниц нет `CollectionPage` / `Place`
Есть `ItemList`, но страница не заявляет, что она про место. `Place` / `CollectionPage` с `about: Place` дешевле всего добавить именно здесь — это основные коммерческие посадочные.

**Severity: Medium.**

## 5. Мусор из шаблона

### C10. Демо-вилла из Майами в языковых файлах всех шести локалей
`messages/en.json:130`, и то же в `it/pl/ru/sq/uk`:
```
"address": "20 S Aurora Ave, Miami",
"description": "Experience luxury living at modern luxe villa, located at 20 S Aurora Ave, Miami. Priced at $1,650,500, this 560 ft² smart home…"
```
Это дефолты секции `featured` из исходного шаблона. Строки уезжают в payload каждой страницы (видны в HTML главной), то есть краулер их читает: американский адрес, цена в долларах и площадь в квадратных футах на сайте албанского агентства.

**Severity: High.** Удалить из всех шести файлов; если секция может остаться без данных CMS — рендерить ничего, а не Майами.

### C11. `format-detection: telephone=no, address=no, email=no`
Мелочь, но на сайте, где звонок — целевое действие, отключать распознавание телефона на мобильных незачем.

**Severity: Low.**

## 6. Авторитет и видимость

### C12. Бренда не существует в выдаче
Поиск «domlivo Albania real estate» не возвращает сайт вообще — только конкурентов (realestate.al, duashpi.al, indomio.al, remax-albania.com, albaniapropertygroup.com). По `site:domlivo.com` находится одна страница агента.
Ahrefs (26.08.2026): DR 0, UR 0, organic keywords 0, при 821 бэклинке с 452 доменов; AI-упоминаний 0 на всех платформах.

452 ссылающихся домена при DR 0 — это почти наверняка каталоги/виджеты/скрейперы, не передающие вес. Проверка качества профиля — отдельная задача (идёт).

**Severity: Critical (для бизнеса, не для кода).** Пока нет ни одной внятной входящей ссылки и ни одного упоминания бренда, техническая часть роли не играет.

### C13. Common Crawl не знает домен вообще
Веб-граф Common Crawl (релиз `cc-main-2026-jan-feb-mar`):
```json
{"domain":"domlivo.com","in_crawl":false,"in_rankings":false,
 "pagerank":null,"harmonic_centrality":null,"n_hosts":null}
```
Домена нет ни в краулe, ни в рейтингах — ни PageRank, ни harmonic centrality.

Оговорка, без которой вывод был бы нечестным: этот релиз покрывает январь–март 2026, а контент сайта датируется мартом 2026. Часть отсутствия объясняется тем, что снимок старше сайта.

Но с Ahrefs (26.08.2026: 821 бэклинк с 452 доменов, DR 0) это складывается в одну картину: **ссылок, которые видит открытый веб-граф, у домена нет**. То, что показывает Ahrefs, почти наверняка каталожные и скрейперные страницы, не попадающие в основной краул и не передающие веса.

Практический вывод для плана: не тратить время на аудит и disavow существующего профиля — там нечего чистить. Строить ссылочное с нуля.

**Проверить заново**, когда выйдет релиз Common Crawl за осень 2026 — тогда отсутствие домена уже нельзя будет списать на возраст снимка.

| realestate.al | да | 2 736 765 | 14 246 701 | 2 |
| century21albania.com | да | 4 504 411 | 14 965 089 | 2 |
| realdeal.al | да | 5 211 943 | 7 663 899 | 2 |

| indomio.al | да | — | — | — |
| sarajrealestate.com | да | — | — | — |

Два вывода, и они разные.

**Планка низкая.** century21albania.com — №3 по доле трафика в EN-выдаче — стоит на 4.5 млн месте по PageRank и 15 млн по harmonic centrality. Это почти ничто. Единственный, кто заметно оторвался, — duashpi.al (harmonic rank 160 тыс., на два порядка выше остальных); он же лидер рынка по объявлениям. Остальные — досягаемы малой кровью, что согласуется с наблюдением из Ahrefs: сайты с DR 0–7 сидят в топ-10.

**Но domlivo ниже входного порога.** Конкуренты в краулe все до одного, domlivo — нет. Первая цель ссылочного, следовательно, не «обогнать century21», а более скромная: **попасть в веб-граф вообще**. Для этого нужно, чтобы на сайт ссылалось несколько реальных хостов, которые Common Crawl уже краулит.

Оговорка та же, что в C13: снимок графа старше сайта, часть разрыва объясняется возрастом. Но у конкурентов `n_hosts` = 1–2, то есть и они держатся на единицах ссылающихся хостов — цель измеряется единицами ссылок, а не сотнями.
