# База знаний на сайте — что построено (2026-09-12)

Проект: [TZ-AI-KNOWLEDGE-BASE.md](TZ-AI-KNOWLEDGE-BASE.md). Здесь — что реально сделано, как этим пользоваться и что осталось.

Исследование живёт в `DomLivo Research Department/knowledge-base/12-ai-database/`. Сайт берёт оттуда данные через импорт в Sanity; сам исследовательский репозиторий остаётся местом авторства.

---

## 1. Что уже работает

| Слой | Состояние |
|---|---|
| Типы в Sanity | `knowledgeSource`, `knowledgeFact`, `knowledgeArticle` + объекты `knowledgeSection`, `knowledgeTable`; раздел «Knowledge Base» в Studio |
| Данные в Sanity | 386 источников, 425 фактов (369 из исследования + 56 производных параметров), 23 статьи, 141 таблица, 1381 строка |
| Ассистент | читает все факты из закэшированного блока промпта; инструменты `lookup_facts`, `calc_utilities`, `cite`; ответы приходят с чипами источников |
| Расчёты | `src/lib/calculators/utilities.ts` — порт `calc_engine.py`, 16 тестов на совпадение с исследованием |
| Страницы | `/[locale]/knowledge` и `/[locale]/knowledge/[slug]`, якоря на строки таблиц, источники под каждой таблицей, блок «чего не хватает», JSON-LD `Dataset` + `FAQPage` |
| Публичный API | `GET /api/knowledge/facts?ids=…` и `?category=&city=&q=&limit=` |
| Инфраструктура | `sitemap-knowledge.xml`, теги ревалидации для трёх новых типов, i18n-словарь `Knowledge` на шести языках |

Статьи импортированы **неопубликованными**. Ассистент это не блокирует: он отвечает по фактам и ссылается на первоисточник; ссылка на страницу базы появляется в чипе только после публикации.

## 2. Что нужно для деплоя

**`SANITY_API_TOKEN`** (read-доступ) в окружении фронтенда. Публичный грант датасета покрывает типы каталога, но не типы базы знаний — анонимный клиент видит 407 объектов и ноль фактов. Без токена чтения возвращают пусто, и ассистент честно отвечает «данных нет» вместо того, чтобы выдумывать.

Так и задумано: неопубликованная статья и стоящие за ней факты не должны быть доступны через публичный Sanity API. Альтернатива — расширить грант датасета на три типа, тогда токен не нужен; код это поддерживает (падает обратно на публичный клиент).

## 3. Команды

Импорт (в `domlivo-admin`, требует `.env` с `SANITY_API_TOKEN`):

```bash
npm run knowledge:sources    # dry run; :apply — записать
npm run knowledge:facts
npm run knowledge:articles
npm run knowledge:import     # всё подряд, с записью
```

Проверка и публикация:

```bash
npm run knowledge:verify                                   # количества и образец документа
npm run knowledge:audit                                    # проверки правдоподобия значений
npx tsx scripts/knowledge/setKnowledgePublished.ts --on UTIL-ELEC-ALB-2026
npx tsx scripts/knowledge/setKnowledgePublished.ts --on --all
```

Импорт идемпотентен: `_id` выводится из `sourceId` / `dataId` / `documentId`, повторный запуск обновляет на месте. Поля, ставшие пустыми, снимаются, а не остаются от прошлого прогона.

Статьи импортируются дважды при первом запуске: первый проход создаёт производные факты, второй проставляет на них ссылки из строк.

## 4. Что чинилось по дороге (и на что смотреть при следующем импорте)

Эти ошибки уже исправлены, но они показывают, где парсер хрупкий:

1. **Коды релизов INSTAT как идентификаторы источников.** «T4-2025» подходило под шаблон и превращалось в ссылку на несуществующий документ — вся транзакция падала. Теперь идентификатор обязан заканчиваться ровно тремя цифрами, а неизвестные ссылки отбрасываются с предупреждением, а не роняют импорт.
2. **Единицы от оригинала при нормализованном значении.** Хранилось `0.092` рядом с «ALL per kWh» — читается как 0.092 лека, ошибка в сто раз. Теперь единица приводится к евро вместе со значением, а лек остаётся в `originalValue`.
3. **Первое число из прозы вместо величины.** «Q3-2022», «n=18», «6th floor», «1+1» попадали в значение — получались аренды по 3 и 18 евро. Теперь число берётся либо из явного поля нормализации, либо с начала строки, либо там, где рядом стоит единица измерения.
4. **Патч без снятия полей.** Исправленный парсер оставлял старое неверное значение в документе, потому что патч выставлял только определённые поля.
5. **CRLF в сгенерированном файле** сделал блок метаданных невидимым — документ молча переставал импортироваться.
6. **Слаг города.** В каталоге `sarande`, в импорте было `saranda`: 28 фактов Саранды остались без привязки, а ассистент искал несуществующий слаг и отвечал про другой город.
7. **Ранжирование поиска.** Национальные факты (HIGH) вытесняли городские, и на вопрос про Саранду возвращались только общеалбанские строки. Теперь при фильтре по городу его факты идут первыми.
8. **Дубли якорей.** Один факт стоит за несколькими строками страницы, и `id` повторялся — ссылка вела не туда. Первая строка получает чистый `data_id`, остальные — якорь в пределах таблицы.
9. **Маршрутизация вопросов.** Промпт открывался фразой «посетитель описывает, что хочет найти», и вопрос про коммуналку превращался в поиск квартир. Добавлен раздел «какой это вопрос» и правило не подменять названный город.

`npm run knowledge:audit` проверяет пункты 2–3 автоматически: аренда меньше 50 €, цена за м² меньше 100 €, тариф вне диапазона, процент больше 100, единица в леках при нормализованном значении. Сейчас 0 срабатываний.

## 5. Что осталось

| Что | Почему важно |
|---|---|
| Перевести статьи (ru/sq/uk/it/pl) и опубликовать | Сейчас тексты только на английском; публиковать английскую страницу на шести локалях — плодить дубли |
| Ссылка на `/knowledge` в навигации и подвале | Раздел не найти иначе как по прямому адресу |
| Виджет «экономика владения» на карточке объекта и странице района | ТЗ §4.3; данные и расчёт уже есть |
| Инлайн-блок `knowledgeTableEmbed` для блога | Чтобы цифры в постах не копировались руками |
| Недельный отчёт о просроченных фактах | Поля `nextReviewAt` и `lastVerifiedAt` заполнены, cron ещё нет |
| 11 фактов без ссылки на город (`geography` текстом: Ksamil, Golem, Vlorë County) | Поиск по городу их не найдёт |
| `DATA-PROPERTY-DURRES-0028` без источника | Единственный факт без первоисточника; в исследовании он помечен как снятый со сниппетов поиска |
