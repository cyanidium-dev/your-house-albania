# ТЗ: городские и районные страницы

Что должно быть на странице города, в хабе районов и на странице района, чтобы
город считался закрытым. Написано по итогам разбора Дурреса 2026-09-09 и
применено к Тиране, Влёре и Саранде. Для следующего города — работать по этому
списку сверху вниз.

Проверка текущего состояния одной командой — см. §6.

---

## 1. Откуда берутся данные

| Что | Где живёт | Кто заполняет |
|---|---|---|
| Цены, диапазоны, доходность, источники | `zoneMetrics` (Sanity), сид — `domlivo-admin/scripts/data/zone-metrics-seed.json` | сид-скрипт |
| Факты для текстов | поле `notes` того же сида (en/ru) | оттуда же |
| Описание района | `district.description` | `scripts/data/zoneEditorialCopy.ts` |
| Текст на странице города | `CITY_EDITORIAL_COPY` там же | там же |
| Фото района | `district.heroImage` + `gallery` | `applyZoneImages.ts`, только с лицензией |

**Правило номер один: цифра в тексте и цифра в таблице на той же странице
берутся из одной записи `zoneMetrics`.** Если факта нет в сиде или в
`shortDescription` — его нет и в тексте. Ничего не досочиняем: страница
публичная, и выдуманная цена — это не «SEO», а дезинформация покупателя.

Если по зоне данных нет вообще — см. §5, зона остаётся без таблицы, но с текстом.

---

## 2. Страница города (`landingPage`, `pageType: "city"`)

Обязательный состав секций:

1. `heroSection` — H1 с городом и годом
2. `zoneStatsAutoSection` или `zonePriceTableAutoSection` — цифры по зонам
3. `propertyCarouselSection` — объекты города
4. **`seoTextSection` — ровно один**, с фотографией
5. `relatedPagesAutoSection` — **ровно один блок районов**
6. `faqSection` / `articlesSection` — по наличию

### 4. Текстовый блок — что в нём должно быть

- **Заголовок** — не «Описание Дурреса» (это подпись поля в CMS, а не H2).
  Формат: `Где покупать в {городе}: районы и цены` во всех шести локалях.
- **Фотография** — поле `image` в `seoTextSection`. Берём `city.gallery[0]`,
  а не `heroImage`: герой уже стоит наверху той же страницы. С фотографией
  блок раскрывается на всю ширину страницы, без неё — остаётся колонкой
  для чтения.
- **Тело — лестница зон с цифрами.** Это главное. Не «город с высоким
  спросом на жильё», а: дорогая зона → средние → дешёвые, у каждой диапазон
  €/м², плюс средняя по городу и одна честная оговорка (см. §4).
  Ориентир — 600–800 знаков, 6–10 названий районов.

### Чего на странице города быть не должно

- **Второго `seoTextSection`** с текстом вида «Domlivo помогает находить
  проверенные предложения». Фактов ноль, вес страницы делится надвое.
- **`linkedGallerySection` без подписей.** В Дурресе и Тиране это были
  десять стоковых фото (закат, горы, северный порт) со ссылками на
  `/catalog?...`, из них две — на несуществующие районы `area-1` и `area-2`,
  и стоял он прямо над блоком районов с настоящими фото. Снесено скриптом
  `purge:seed-galleries`. Признак сида: **ни у одного элемента нет `title`** —
  двенадцать галерей на страницах сравнений подписаны и остаются на месте.
- **Двух блоков районов.** Один `relatedPagesAutoSection` — и всё.

## 3. Хаб районов (`/{country}/{city}/districts`)

- Карточка на каждый опубликованный район: фото, название, `shortDescription`,
  число объектов.
- **Фото — только с зафиксированной лицензией** (`imageCredit`), по правилам
  `applyZoneImages.ts`: снимок самого района подписывается его именем, чужой
  снимок помечается STAND-IN и описывает то, что на нём изображено. Стоковый
  закат вместо района — хуже, чем отсутствие фото.
- Района без фото карточка не ломает: `EntityCard` рисует фирменную плашку
  с пином. Это заглушка «фото будет», а не «фото сломалось», но она не
  отменяет задачу найти снимок.

## 4. Страница района

Если есть `landingPage` с `pageType: "district"` — она выигрывает у шаблона.
Состав (его же генерирует `generateDistrictLandings.ts`):

1. `heroSection` — H1 `{Район}, {Город}: цены на недвижимость {год}`
2. `zoneStatsAutoSection` — цифры + `notes` из `zoneMetrics`
3. **`seoTextSection` «О районе {N}»** ← этого не хватало
4. `propertyCarouselSection` — объекты района
5. `zonePriceTableAutoSection` (mode: compare) — три ближайших по цене
6. `relatedPagesAutoSection` ×2 — соседи и сравнения
7. `ctaSection`

### Ловушка, из-за которой всё и произошло

`generateDistrictLandings.ts` ставит блок 3 **только если**
`district.description.en` длиннее 150 знаков. Тринадцать районов по четырём
городам не проходили этот порог — часть с пустым полем, часть с сид-фразой
вроде «Beachfront offers direct beach access in Durres» — и получали лендинг
с цифрами, объектами и ссылками, но без единой строки текста. Причём это были
ровно коммерчески главные районы: центр, пляж, Голем, Плепа, Шкемби, Шкозет,
Лунгомаре, центр Влёры, Ксамиль, центр Саранды.

**Поэтому: описание района пишется ДО генерации лендинга.** Порог 150 знаков —
это не рекомендация, это условие существования блока.

### Формат описания района (600–700 знаков)

Четыре вещи, в таком порядке — по образцу Черрета и Спилле, которые изначально
были написаны правильно:

1. **Диапазон** €/м² и динамика год к году.
2. **Как цена меняется внутри зоны** — по расстоянию до моря, по возрасту
   фонда, по сегментам. Это то, чего нет в таблице.
3. **Кто покупает** — местные, диаспора, поляки и чехи, инвесторы.
4. **Одна честная оговорка**, которую покупатель иначе узнает поздно.
   Не рекламная, а настоящая:
   - Черрет административно относится к Bashkia Kavajë, а не к Дурресу —
     разрешения ведёт другой муниципалитет;
   - в Големе — сток канализации на пляж;
   - у Уйи-и-Фтохте диапазон **расчётный, а не измеренный** (–20–25% от
     Лунгомаре), так и написано;
   - в Ксамиле 522 объявления при загрузке 38,3% — на аренду покупать не выходит;
   - в Саранде иностранный спрос падал два года подряд, а цены росли;
   - в центре Дурреса нотариус считает от справочной таблицы, а не от сделки.

Оговорка — не риск для конверсии, а единственное, что отличает страницу от
сотни таких же. Она же — то, что цитируют AI-ответы.

### Локали

Пишем `en` и `ru` руками. Остальные четыре (`uk`, `sq`, `it`, `pl`)
**не переводим вручную и не оставляем на английском**:

```
npm run apply:zone-editorial     -- --dry   # затем --execute
npm run translate:zone-editorial -- --dry   # затем --execute
```

Важно: `apply` **стирает** локали, которых не пишет. Это сделано намеренно —
переписанный английский абзац рядом с сид-фразой на итальянском хуже, чем
пустота. Поэтому порядок всегда `apply` → `translate`, и повторный `apply`
на уже переведённом блоке ничего не трогает (нужен `--force`).

## 5. Зона без цифр

Кавая и Спилле — не квартирный рынок, а земля и дома, и в `zone-metrics-seed`
их сознательно нет. Такая зона:

- **не получает** `zoneMetrics` с выдуманным €/м² и не попадает в таблицу цен;
- **получает** описание в `district.description` — оно и есть содержание страницы;
- рендерится шаблоном `DistrictPageBody`, который при отсутствии фото
  подставляет снимок города с честным alt.

Отдельный `landingPage` такой зоне не нужен.

## 6. Чек-лист приёмки города

```bash
# из domlivo-admin, подставить слаг города
npx tsx -e "…"   # либо GROQ ниже в Vision
```

GROQ для проверки одним запросом:

```groq
*[_type == "district" && city->slug.current == $city && isPublished == true]{
  "s": slug.current,
  "desc": length(coalesce(description.en, "")),        // >= 150
  "hero": defined(heroImage.asset),                     // true
  "about": count(*[_type == "landingPage" && pageType == "district" &&
                   linkedDistrict._ref == ^._id][0].pageSections[_type == "seoTextSection"]),
  "metrics": count(*[_type == "zoneMetrics" && zone._ref == ^._id])
} | order(s asc)
```

Плюс по странице города:

```groq
*[_type == "landingPage" && pageType == "city" && linkedCity->slug.current == $city][0]{
  "seoText":   count(pageSections[_type == "seoTextSection"]),          // ровно 1
  "gallery":   count(pageSections[_type == "linkedGallerySection"]),    // 0
  "districts": count(pageSections[_type == "relatedPagesAutoSection"])  // ровно 1
}
```

## 7. Что было починено в коде заодно

Эти баги делали данные хуже, чем они есть, — их стоит помнить при разборе
следующего города:

- **Таблица цен по зонам съезжала на колонку.** `PriceTableSection` рисует
  собственный заголовок для колонки-подписи, а `ZonePriceTableAutoScection`
  дополнительно клал «Зона» первым элементом `columns` — в результате каждая
  цена стояла под чужим заголовком. Появилось поле `labelHeader`.
- **Колонка из прочерков.** Колонка оставалась, если её заполняла хотя бы одна
  строка: у Шкемби единственного есть `priceNew`/`priceResale`, и эта одна
  запись держала две пустые колонки на тринадцать строк. Теперь колонке нужна
  половина строк.
- **`seoTextSection` не умел фотографию** — добавлено поле `image` в схему и
  рендер; с фотографией блок раскрывается на всю ширину.
- **Карточка района без фото** была плоским серым прямоугольником, читалась
  как битая картинка. Теперь фирменная плашка с пином.
