# Field CLS and JS errors — October 2026

Starting point (audit 2026-10-18): Clarity reports CLS 0.41 in the field (0.63
in sessions with dead clicks) while Lighthouse shows ~0. JS errors on listing
and catalogue pages: `insertBefore`/`removeChild` on Node (33 %), `Maximum call
stack size exceeded` (22 %), `ResizeObserver loop`.

## How it was measured

Local production build (`next build && next start`), headless Chrome 141 via
puppeteer-core, a script that records every `layout-shift` entry with its
sources (`PerformanceObserver`, `buffered`), groups them into session windows
(1 s gap, 5 s cap) like CLS does, and prints the moved nodes with their
before/after rects.

- Phone: 390×844, DPR 2, touch, ~1.6 Mbps / 150 ms RTT, CPU ×4.
- Desktop: 1440×900, no throttling.
- Each run: load, 6 s idle, scroll to the bottom in 300 px steps, back up,
  12 s idle (covers the PWA invitation timer and the 5 s analytics loader).
- Pages: `/ru/property/…` (listing), `/ru/albania/durres` and `/ru/sale`
  (catalogue), `/uk/blog/albania-protests-property-market-impact` (article),
  `/ru/albania/durres/districts/plazh` (district).

## JS errors

### `insertBefore` / `removeChild` NotFoundError — reproduced and fixed

Reproduction: open `/ru/albania/durres`, let the browser translate the page
(simulated by replacing every text node with Google Translate's
`<font><font>…</font></font>`), press "Show more".

```
NotFoundError: Failed to execute 'insertBefore' on 'Node': The node before which
the new node is to be inserted is not a child of this node.
  parent: <a rel="next" …>   ref: TEXT "Показать ещё объекты"   new: <svg class="animate-spin">
```

The button rendered `{isLoading && <svg/>}{t("showMore")}`: React inserts the
spinner before the label's text node, which the translator had already
replaced. Reproduced on www.domlivo.com as well (not caused by this change).

Fixes:
1. The label sits in its own `<span>` (PropertyPagination), so React's
   reference node is an element the translator leaves in place. A scan of
   client components for "conditional element before a bare text node" found
   no other instance.
2. `lib/dom/translatorGuard.ts`: the guard React's maintainers recommend
   (facebook/react#11538) — when the node React refers to has left the parent,
   `insertBefore` appends and `removeChild` skips instead of throwing. Inline
   in the layout, before hydration, ~400 bytes.

After: the same translated run gives 0 errors (was 1 per "Show more").

### `Maximum call stack size exceeded` — not reproduced

Not seen in any run (listing, catalogue, article; with and without the
simulated translator; gallery, lightbox, currency switch, contact modal, show
more, sort). Checked and ruled out: recursive functions in client code, large
array spreads (`Math.min(...)` only runs on the server), history wrappers.
One leak noted: `nextjs-toploader` wraps `history.pushState/replaceState` on
every mount and never unwraps; a remount (locale switch) adds a layer. It
would take thousands of remounts to overflow the stack, so it is unlikely to
be the cause.

Next step: in Clarity, Recordings → filter "JavaScript errors: Maximum call
stack", look at browser, extensions-heavy desktop vs Android WebView (in-app
browsers of Telegram/Instagram), and the last action before the error.

### `ResizeObserver loop` — benign

Browser notice when an observer's callback changes layout in the same frame
(CatalogFilterCollapse measures the form). It does not break anything; not
changed.
