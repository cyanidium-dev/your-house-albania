# Лиды из мессенджеров — WhatsApp с готовым текстом, Telegram-бот, шторка (2026-10-18)

Почему: 70 % «лидов» за месяц были кликами по WhatsApp/Telegram, после которых человек не писал — открывался пустой чат, а на компьютере часто нет приложения (`reports/domlivo-audit-2026-10-18/CONVERSION-ANALYSIS.md`). Теперь:

1. **WhatsApp** открывается с готовым сообщением на языке посетителя: «Здравствуйте! Интересует {объект}, {цена}: {ссылка}» на странице объекта и «Здравствуйте! Хочу подобрать недвижимость в Албании» + адрес страницы везде ещё. Тексты — `Messengers.whatsappText.*` в `messages/*.json`.
2. **Telegram** ведёт на публичного бота по ссылке `https://t.me/<бот>?start=<payload>`. Нажатие «Старт» в боте уже создаёт лид с Telegram-аккаунтом и объектом и приходит в командный чат.
3. **Шторка** по клику на любую кнопку WhatsApp/Telegram на сайте: большая кнопка «Открыть WhatsApp/Telegram» (один тап) и под ней «или оставьте номер — напишем сами». На компьютере WhatsApp открывается в WhatsApp Web.
4. **Лидом считается** старт бота (`telegram_start`), сообщение боту и отправленный номер (`contact_form`). Клик по кнопке остаётся событием-намерением `click_whatsapp` / `click_telegram`.

## Что сделать владельцу

### 1. Номер WhatsApp (без него текст не подставится)

Ссылка в CMS сейчас — короткая ссылка WhatsApp Business `wa.me/message/KPXIGD5DJISGO1`. Такая ссылка **не принимает готовый текст** (WhatsApp подставляет только сообщение, настроенное в приложении). Для текста нужен номер, на который пишут клиенты.

Любой из двух вариантов:

- задать на Vercel `NEXT_PUBLIC_WHATSAPP_NUMBER` — номер в международном формате, например `355691234567` (можно с `+` и пробелами);
- или в Studio → Site settings → Social links заменить ссылку WhatsApp на `https://wa.me/355691234567`.

Пока номера нет, кнопки WhatsApp ведут на прежнюю короткую ссылку (как сейчас), шторка работает, поле для номера работает.

### 2. Создать бота у @BotFather

Бот создан 2026-10-19: **[@DomlivoAlbaniaBot](https://t.me/DomlivoAlbaniaBot)**. Для нового бота — так же:

1. В Telegram открыть [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Имя (видно в чате): `Domlivo`.
3. Username (должен кончаться на `bot`): `DomlivoAlbaniaBot`. Служебный бот доставки заявок (`@domlivobot`, `TELEGRAM_BOT_TOKEN`) не трогаем — это другой бот.
4. BotFather пришлёт токен вида `123456789:AA…`. Никому не пересылать.
5. Там же: `/setuserpic` — логотип Domlivo. Описание и команды ставит скрипт (шаг 5) на 7 языках.
6. Режим приватности (`/setprivacy`) **не менять** — пусть остаётся включённым: в группе бот видит только ответы на свои сообщения, этого достаточно.

### 3. Переменные на Vercel (Project → Settings → Environment Variables, Production)

| Переменная | Значение |
|---|---|
| `TELEGRAM_PUBLIC_BOT_TOKEN` | токен нового бота от BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | любая случайная строка 32+ символа из `A-Z a-z 0-9 _ -` (например, из генератора паролей без спецсимволов) |
| `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` | `DomlivoAlbaniaBot` (без `@`) |
| `NEXT_PUBLIC_WHATSAPP_NUMBER` | номер WhatsApp, см. шаг 1 |

Уже должны быть (их используют формы): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_GENERAL_CHAT_ID`, `SANITY_API_TOKEN`.

После добавления — **Redeploy** (переменные `NEXT_PUBLIC_*` попадают в сборку только при новом деплое). Пока `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` не задан, Telegram-кнопки ведут на прежний `t.me/real_estate_al`.

### 4. Добавить бота в командный чат

Добавить нового бота участником в группу, куда приходят заявки (`TELEGRAM_GENERAL_CHAT_ID`), и в группы агентств, у которых в Studio задан свой чат (`agent.telegramLeadChatId`). Права администратора не нужны.

Если бот в группу не добавлен, лид всё равно придёт — его отправит служебный бот, но отвечать клиенту через reply не получится (только напрямую по ссылке на профиль).

### 5. Запустить скрипт вебхука (один раз, и снова при смене домена или текстов)

В корне репозитория создать (или дополнить) `.env.local`:

```
TELEGRAM_PUBLIC_BOT_TOKEN=…
TELEGRAM_WEBHOOK_SECRET=…            # тот же, что на Vercel
NEXT_PUBLIC_TELEGRAM_BOT_USERNAME=DomlivoAlbaniaBot
NEXT_PUBLIC_SITE_URL=https://www.domlivo.com
```

и запустить:

```bash
node --env-file=.env.local scripts/telegram-set-webhook.ts
```

Скрипт проверит токен, поставит вебхук `https://www.domlivo.com/api/telegram/webhook` с секретом, команду `/start` и описание бота на 7 языках (тексты — `TelegramBot.*` в `messages/*.json`). Проверка состояния: `--info`, снять вебхук: `--delete`.

### 6. Проверить

1. Открыть любой объект на сайте → Telegram → «Открыть Telegram» → «Старт».
2. Бот ответит карточкой объекта на языке страницы; в командном чате появится «🤖 Лид из Telegram-бота» с объектом.
3. Написать боту вопрос — он придёт в чат с подписью «Имя, RU, объект …».
4. Ответить в чате **reply** на это сообщение — клиент получит ответ от бота, на ответе менеджера появится 👍.

## Как работать с лидами

**В командном чате:**

- «🤖 Лид из Telegram-бота — нажал «Старт»» — человек открыл бота с сайта. Видно: имя и @username (ссылка на профиль), язык, где на сайте нажал, объект со ссылкой.
- «💬 Имя, RU, объект …» — сообщение клиента боту (текст, фото, голосовое, документ — с той же подписью). «📱 Номер: +…» — клиент нажал «Отправить мой номер».
- **Ответ клиенту:** reply (ответить) на любое из этих сообщений бота. Бот перешлёт ответ клиенту от своего имени — текст, фото, голосовое. 👍 на вашем ответе = доставлено; «⚠️ Не доставлено» = клиент заблокировал бота или не нажимал «Старт».
- Обычные сообщения в чате (не reply на сообщение бота) клиенту **не уходят** — можно обсуждать внутри.
- Можно ответить и напрямую: ссылка `https://t.me/<username>` в сообщении о лиде (если у клиента есть username).
- Вся переписка с одним клиентом находится поиском по хэштегу `#tg<id>` из сообщения.

**В Studio (Leads):** тип «Telegram bot start» — один документ на старт (повторный «Старт» по тому же объекту в течение 30 минут новый лид не создаёт). Хранится только Telegram id, @username, имя и язык приложения; номер и сообщения остаются в Telegram-чате. Тип «Contact form» с меткой формы `messenger-sheet:whatsapp` / `messenger-sheet:telegram` — номер, оставленный в шторке.

**В аналитике (GA4/Clarity):** `click_whatsapp` / `click_telegram` — открыл шторку (намерение); `messenger_open` — нажал «Открыть WhatsApp/Telegram» в шторке (`web: true` — WhatsApp Web на компьютере); `generate_lead` — оставил номер.

## Подписка на новые объекты (search alerts, 2026-10-19)

Над карточками каталога (и в пустой выдаче) стоит блок «Новые объекты по этому поиску - раз в день в Telegram». Ссылка ведёт в бота с payload `s_<locale>_<фильтры>` (город, район, тип, сделка, цена, площадь, спальни, стадия, у моря, инвестиции - всё, что умещается в 64 символа). Нажатие «Старт» = подписка:

- бот отвечает на языке сайта: «Готово», пересказ поиска словами, до 3 текущих объектов со ссылками, кнопка «Открыть поиск на Domlivo», подсказка `/stop`, и второе сообщение с предложением написать менеджеру или отправить номер;
- в Studio появляется документ **Search alerts** (поиск, язык, имя, @username, что уже отправлено); у одного аккаунта не больше 5 активных - шестая выключает самую старую;
- в командный чат приходит лид «подписался на новые объекты» с пересказом поиска и ссылкой на выдачу - отвечать reply, как на любой лид бота;
- каждый день в 07:00 UTC (`vercel.json` → `/api/cron/search-alerts`, нужен `CRON_SECRET`) бот присылает до 5 объектов, созданных после подписки и ещё не отправленных, новее - выше; объект никогда не уходит дважды;
- `/stop` выключает все подписки аккаунта; заблокировавших бота крон выключает сам.

Отключить можно и в Studio: Search alerts → документ → Active off. Вручную запустить рассылку: `GET https://www.domlivo.com/api/cron/search-alerts?secret=<CRON_SECRET>` (ответ: сколько проверено, отправлено, выключено).

## Как устроено (для разработчика)

| Часть | Файл |
|---|---|
| Payload бота (`p_<locale>_<slug>`, `i_<locale>_<id без property->` для длинных слагов, `g_<locale>_<placement>`) | `src/lib/telegram/startPayload.ts` |
| Подписка на поиск: пересказ фильтров, ссылка на выдачу, документ `searchSubscription`, выборка новых объектов | `src/lib/telegram/bot/search.ts`, крон `src/app/api/cron/search-alerts/route.ts`, блок `src/components/catalog/CatalogSearchAlert.tsx` |
| Ссылки: текст WhatsApp, номер, WhatsApp Web, deep link, достройка ссылки в момент клика | `src/lib/contacts/messengerLinks.ts` |
| Текст сообщения и payload для места на сайте | `src/lib/contacts/messengerContext.ts` (+ `.server.ts`) |
| Кнопки: CMS-ссылка + контекст | `resolveMessengers(links, locale, context)` в `src/lib/contacts/messengers.ts` |
| Шторка | `src/components/contact/MessengerSheet.tsx`, открывается из `LeadTracker` (перехват обычного клика по `wa.me`/`t.me`; Ctrl/⌘-клик и `data-messenger-direct` — сразу в приложение; `data-messenger-plain` — без общего текста) |
| Вебхук | `src/app/api/telegram/webhook/route.ts` → `src/lib/telegram/bot/handleUpdate.ts` |
| Тексты бота | `TelegramBot.*` в `messages/*.json` |
| Тип лида | `telegram_start` в `src/lib/leads/types.ts` и в схеме `lead` (domlivo-admin) |

Ссылки, которые сервер не может собрать полностью (футер в layout, «О нас»), шторка достраивает в браузере: добавляет общий текст и адрес страницы, а Telegram — payload с реальным placement или с объектом из адреса страницы.
